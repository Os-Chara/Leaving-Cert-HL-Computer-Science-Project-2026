Key Milestones


Embedded System:

Milestone-1: The DHT22 and capacitive soil moisture sensor were connected to the Raspberry Pi Pico W on a breadboard, with readings printed directly to the Thonny shell via serial connection.
Test: Conditions were manually altered by breathing on the DHT22 and submerging the soil moisture sensor to verify both sensors were responding accurately to real environmental changes.

Milestone-2: I soldered stackable headers to the Pico W, as the OLED display covered all pins, allowing simultaneous attachment of all components.
Test: A multimeter was used to verify continuity across each solder joint, the components were then wired, and sensor data was printed to the OLED display to confirm functionality.

Milestone-3: I designed a custom enclosure in Fusion 360 with precise measurements for my components, which I then 3D printed.
Test: I printed the smallest piece first so I could identify structural issues to rectify.

Milestone-4: Components were wired and assembled into their final positions.
Test: A MicroPython test script was run to confirm all components were wired and functioning correctly.

Milestone-5: I created algorithms to identify the relative risk level from each of my variables in Python. Each function was designed to return a probabilistic value between 0 and 1 using exponential formulas derived from Desmos.
Test: Each function was tested by using known benchmark values. For soil moisture, physical benchmarks were established by submerging the sensor in water, and wet and dry soil. These readings were then used to calibrate the function so that risk output corresponded accurately to real world conditions. Similarly for humidity, readings under typical conditions were used to get a baseline, and readings in humid and dry environments found the range for the function.

Milestone-6: An overall risk level was then found by creating a weighted average of the 3 variables. When the risk passes a certain threshold, the buzzer and LED activate.
Test: Using a hair dryer and soil samples of varied moisture, I verified that the warning system would only activate in extreme conditions.


Disaster Model

Milestone-1: A data retrieval system was built to request CSV data from the Pico W via HTTP over WiFi and store it locally.
Test: The Pico's IP address was identified using a MicroPython script, and correct data formatting was confirmed by printing received rows to the shell.

Milestone-2: What-if scenarios were developed by altering variables to simulate climate change and drought conditions.
Test: Scenarios were tested using simulated datasets to confirm expected changes in risk output.

Milestone-3: A graphing function was created to visualise all three scenarios across three subplots without repeating code.
Test: Various tuples containing mixtures of the data from different scenarios were inputted to verify it can handle varied data.

Problem Encountered:


During an early iteration of my code, I attempted to assign a risk level to the temperature using a threshold system. My goal was to create a system where a small increase in temperature had little effect on risk at low temperatures but a greater increase per degree at higher temperatures.
In this regard my code worked well, but I noticed the problem when I graphed temperature risk; the level would remain horizontal before jumping up or down. This was detrimental as it greatly reduced precision.

I identified that an exponential function would have the desired characteristics with more precision. I went onto desmos.com [19] an online graphing calculator to create a formula with the following characteristics.


  • The output should be clamped between 0 and 1 to give a probabilistic risk value.
  • Risk should be negligible under 17.5°C; high average temperature in Ireland.
  • It should accelerate in the mid-twenties; uncommonly hot summer weather.
  • It should then max out as it reaches the thirties; hottest heat wave weather.



The final formula I developed was:

Risk = (1.2^(x-17.5))/10
0 ≤ Risk ≤ 1

Description of Model:


The user is first asked to select what dataset they wish to use. If one of the locally stored datasets is selected, it is immediately loaded. If they select “request new data”, the model reads the data directly from the Pico via http over WiFi and stores it locally.

Three individual risk functions convert each raw sensor value into a probabilistic risk score between 0 and 1. Temperature risk increases exponentially above 17.5°C using the formula Risk = (1.2^(x-17.5))/10, reflecting Ireland's climate where significant wildfire risk only emerges at uncommonly high temperatures. Humidity risk uses an exponential decay formula, where risk falls as humidity rises above 70%. Similarly, soil moisture risk decreases exponentially as readings rise, indicating wetter soil conditions. All three functions clamp their output between 0 and 1.

These three values are then combined into an overall wildfire risk factor using a weighted average, with temperature weighted most heavily at 0.4, and humidity and soil moisture each weighted at 0.3, reflecting temperature's dominant role in wildfire risk.

The model then produces two what-if scenarios. The first simulates a climate change projection by increasing temperature by 4°C. The second simulates drought conditions by reducing air humidity by 15% and soil moisture by 7.5%. The data for each of the 3 scenarios are saved in 3 tuples, allowing the same graphing function to be reused for all scenarios.

Each tuple is unpacked and inserted into the graph function one by one, from which 3 subplots are created to display overall risk, the raw sensor values, and the risk level by variable. The mean risk of each of the scenarios are calculated, compared, and printed.
